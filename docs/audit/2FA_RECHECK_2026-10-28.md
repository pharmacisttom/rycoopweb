## Finding: QR สำหรับตั้งค่า MFA สแกนไม่ผ่าน

- `tests/QrCodeGeneratorTest.php` เดิมตรวจเพียง SVG/data URI structure การผ่านสองข้อนี้ไม่ยืนยันว่า QR ถอดรหัสได้
- ใช้ QR byte-mode ECC M ของ `QrCodeGenerator` เทียบ Python qrcode และอ่านด้วย jsQR 1.4.0 แยกจาก encoder ไม่ส่ง payload ออกไปยัง API ภายนอก
- ข้อความ `HELLO` (QR version 1): ภาพจากระบบและภาพอ้างอิงถอดรหัสได้ทั้งคู่
- Synthetic OTP URI (QR version 7): ภาพจากระบบถอดรหัสไม่ได้ แต่ภาพอ้างอิงถอดรหัสได้เป็น payload เดิม
- Payload ทดสอบเป็นข้อมูลสังเคราะห์ที่เปิดเผยได้ ไม่ใช่บัญชีหรือ secret จริง:

```text
otpauth://totp/RayongCoop%3Afixture%40example.invalid?secret=JBSWY3DPEHPK3PXPJBSWY3DPEHPK3PXP&issuer=RayongCoop
```

Source ที่เกี่ยวข้อง: `app/Services/QrCodeGenerator.php`
ตรวจพบว่า `createCodewords()` ทำ Reed–Solomon กับข้อมูลก้อนเดียวแล้วต่อท้ายทั้งหมด ไม่แยก/interleave QR blocks และ `generateMatrix()` ไม่เขียน version information สำหรับ version 7 ขึ้นไป
ต้องแก้ encoder หรือใช้ไลบรารีที่ผ่านการทดสอบ โดยรักษาการสร้าง QR ภายในเครื่อง/server ห้ามส่ง secret จริงไปบริการ QR ภายนอก
ต้องเพิ่ม regression ที่อ่าน QR กลับเป็น OTP URI เดิม ทั้ง payload สั้น/ยาว/อีเมลหลายความยาว และยืนยันการสแกนด้วย Authenticator จริงบน TEST ก่อน deploy
ระหว่างนี้การกรอก setup secret ด้วยมืออาจเลี่ยงปัญหา QR ได้ แต่ยังไม่ได้ทดสอบกับแอปโทรศัพท์จริงในรอบนี้

เครื่องมืออ่าน QR ติดตั้งเฉพาะ `storage/tmp/2fa-recheck-20261028/decoder` ที่ Git ignore ไม่เปลี่ยน package.json/package-lock.json ของโครงการ และไม่ commit generated secrets, node_modules หรือ log ส่วนตัว

| /api/auth/options | 404 |

| https://test.rayongcoop.org/api/auth/mfa/status | 401 HTML จาก nginx |

ผล 404 อาจเป็นการแยก public/static site ตามแผน deploy หรือ source/routing ยังไม่เปิดส่วน protected ไม่เพียงพอจะชี้ว่า Nginx ผิด configuration โดยไม่มี config จริง
401 ของ TEST ทำให้ยังตรวจ PHP MFA ภายในไม่ได้ ไม่ได้พยายามข้ามการป้องกันหรือใช้ credentials ใด ๆ
ดังนั้นยังไม่ยืนยันว่า 2FA ทำงาน end-to-end บน VPS ต้องตรวจ host/path ที่ต้องการเปิดระบบ, revision, migrations, HTTPS session configuration และทำ UAT ที่ได้รับอนุญาต
