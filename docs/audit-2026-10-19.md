## Migration / database plan

ไม่มี migration ใหม่ และไม่รัน migrate, seed, drop หรือ truncate บนฐานที่มีอยู่ในรอบนี้ ตรวจ migrations 001–016 จาก source เท่านั้น ส่วน CI เดิมใช้ MySQL service แยก `rayongcoop_ci` ต่อ job และสร้าง fixture ใน service ชั่วคราว

ข้อควรตรวจของ migration เดิม: 009 มี upsert/update master rates และ temporary table, 011 เปลี่ยนสถานะ/ข้อความ member-facing content, 012 และ 016 ใช้ information_schema/PREPARE เพื่อเติมคอลัมน์ที่ขาด จึงไม่ควรรันทั้งหมดกับฐานที่มีอยู่โดยไม่ตรวจ migration history และ backup แม้รอบนี้ไม่เปลี่ยน SQL ก็ตาม

ก่อนทดสอบ DB ให้ผู้ดูแลเตรียมฐาน `rycoop_test_*` พร้อม schema/fixtures สังเคราะห์แยกจาก Production และใช้บัญชี DB แยกที่เข้าถึง Production ไม่ได้ ห้ามคัดลอกข้อมูลสมาชิกจริงเข้า test artifacts ห้ามเปลี่ยน DB_DATABASE ของ Production เพื่อทดสอบ

Backup/restore ต้องใช้ credential file สิทธิ์ 0600 นอก repository, สำรอง schema+data ไปยังพื้นที่ private, ทดสอบ restore ลงฐานทดสอบแยกก่อนใช้งานจริง ไม่ใช้ production restore เป็นขั้นตอนอัตโนมัติของ deploy

## Acceptance criteria

| โมดูล | เกณฑ์รับงาน | สถานะ |
|---|---|---|
| Multi-environment | MAIN `/`, TEST `/test/`, legacy build ยังทำงาน | ผ่าน local build/browser |
| Static assets | logo 200 + image MIME, missing file 404, build รวมไฟล์เอง | ผ่าน local HTTP |
| Routing | deep link, lazy page, 404 และ internal links อยู่ใน prefix | ผ่าน local browser/helper tests |
| Preview security | ไม่มี Login/Protected API/POST ไป DB บน HTTP preview | client, PHP integration และ sample server ผ่าน; ต้องยืนยัน Nginx บน VPS |
| Database safety | tests ไม่มี environment ที่แยกชัดเจนต้องหยุดก่อน connect | ผ่าน guard; DB integration รอ isolated fixture |
| RBAC/CSRF | middleware เดิมไม่ถูกถอดหรือข้าม | security regression ผ่าน |
| Dependency security | ไม่มีช่องโหว่ค้างก่อนอนุมัติ Production หรือมีการยอมรับความเสี่ยงเป็นลายลักษณ์อักษร | ยังไม่ผ่าน: 9 advisories |
| Deployment | TEST ก่อน MAIN, backup config, nginx -t, smoke checks, rollback | มีคู่มือ; ยังไม่ deploy |
